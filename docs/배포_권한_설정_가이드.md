# 배포 권한 설정 가이드 (Artifact Registry)

## ❌ 문제 상황

GitHub Actions 배포가 실패하며 다음 오류가 발생할 수 있습니다:
- `denied: gcr.io repo does not exist`
- `Permission denied` when pushing to Artifact Registry
- `Failed to create repository`

## ✅ 해결 방법

### 1단계: GCP 콘솔에서 서비스 계정 확인

1. **GCP Console 접속**
   - https://console.cloud.google.com
   - 프로젝트 선택 (예: `jeonghwa-library-prod-xxxxx`)

2. **서비스 계정 찾기**
   - 좌측 메뉴 → **IAM & Admin** → **Service Accounts**
   - GitHub Actions에서 사용 중인 서비스 계정 찾기
     - 예: `cloud-run-deployer@PROJECT_ID.iam.gserviceaccount.com`
   - 또는 Secrets의 `GCP_SERVICE_ACCOUNT` 값 확인

### 2단계: 필수 권한 부여

서비스 계정에 다음 **역할(Roles)**을 추가하세요:

#### 필수 역할:
1. **Artifact Registry Writer** (`roles/artifactregistry.writer`)
   - Docker 이미지 푸시/풀 권한

2. **Artifact Registry Admin** (`roles/artifactregistry.admin`)
   - 저장소 생성/삭제 권한 (첫 배포 시 필요)

3. **Cloud Run Admin** (`roles/run.admin`)
   - Cloud Run 서비스 배포/관리

4. **Service Account User** (`roles/iam.serviceAccountUser`)
   - 서비스 계정 사용 권한

#### 권한 부여 방법:

**옵션 A: GCP Console 사용 (권장)**
```
1. IAM & Admin → Service Accounts
2. 서비스 계정 클릭 (예: cloud-run-deployer)
3. "권한" 탭
4. "역할 추가" 클릭
5. 다음 역할 추가:
   - Artifact Registry Admin
   - Artifact Registry Writer  
   - Cloud Run Admin
   - Service Account User
6. "저장" 클릭
```

**옵션 B: gcloud CLI 사용**
```bash
PROJECT_ID="jeonghwa-library-prod-xxxxx"
SERVICE_ACCOUNT="cloud-run-deployer@${PROJECT_ID}.iam.gserviceaccount.com"

# Artifact Registry 권한
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SERVICE_ACCOUNT}" \
  --role="roles/artifactregistry.admin"

gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SERVICE_ACCOUNT}" \
  --role="roles/artifactregistry.writer"

# Cloud Run 권한
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SERVICE_ACCOUNT}" \
  --role="roles/run.admin"

# Service Account User
gcloud projects add-iam-policy-binding ${PROJECT_ID} \
  --member="serviceAccount:${SERVICE_ACCOUNT}" \
  --role="roles/iam.serviceAccountUser"
```

### 3단계: Artifact Registry API 활성화 확인

```
1. API & Services → Library
2. "Artifact Registry API" 검색
3. "사용 설정" 클릭되어 있는지 확인
4. 활성화되지 않았다면 활성화 (1-2분 소요)
```

**또는 CLI:**
```bash
gcloud services enable artifactregistry.googleapis.com --project=${PROJECT_ID}
```

### 4단계: GitHub Actions 재실행

권한 설정 후:
1. GitHub 저장소 → **Actions** 탭
2. 실패한 워크플로우 클릭
3. **Re-run all jobs** 클릭

또는 새로운 커밋을 푸시하면 자동 실행됩니다.

## 🔍 권한 확인 방법

현재 서비스 계정의 권한을 확인하려면:

```bash
PROJECT_ID="YOUR_PROJECT_ID"
SERVICE_ACCOUNT="YOUR_SERVICE_ACCOUNT@${PROJECT_ID}.iam.gserviceaccount.com"

gcloud projects get-iam-policy ${PROJECT_ID} \
  --flatten="bindings[].members" \
  --filter="bindings.members:serviceAccount:${SERVICE_ACCOUNT}" \
  --format="table(bindings.role)"
```

## ⚠️ 주의사항

1. **권한 반영 시간**: 권한 변경 후 최대 5분 정도 소요될 수 있습니다.

2. **Workload Identity Federation**: GitHub Actions는 WIF를 사용하므로, WIF 풀에도 권한이 올바르게 연결되어 있어야 합니다.

3. **프로젝트 레벨 권한**: 일부 권한은 프로젝트 레벨에서 설정되어야 합니다.

## ✅ 성공 확인

배포가 성공하면 GitHub Actions 로그에서 다음 메시지를 볼 수 있습니다:
```
✅ Artifact Registry API is enabled
✅ Repository jeonghwa-docker already exists (or created successfully)
✅ Docker build successful
✅ Image pushed successfully
✅ Service deployed successfully
```

## 📞 추가 도움

여전히 실패한다면:
1. GitHub Actions 로그에서 정확한 에러 메시지 확인
2. GCP Console → IAM & Admin → Audit Logs에서 권한 거부 로그 확인
3. 서비스 계정이 올바른 프로젝트에 연결되어 있는지 확인
